# 概念と境界

## 配信元（source）と記事（Item）

**配信元**は `digest.toml` の `[[source]]` 1つ。`type` は読み方（feed / zenn / trending）で、`name` は識別子、`label` は Telegram に出す名前。同じ `type = "feed"` でも、はてブと Qiita は別の配信元になる。

**Item** は配信元から取れた1件。同一性は `Item.key`（正規化した URL）で決め、タイトルでは決めない。タイトルは配信元ごとに表記が揺れ、Haiku も書き換えるため。

## 選別する配信元と、しない配信元

`filter = true` の配信元は、関心外の記事が混ざる前提のもの（はてブ・Zenn）。新着をまとめて Haiku に渡し、選ばれた分を1通（`[filter].header`）で送る。

`filter = false` の配信元は、分野を絞らずに眺めること自体に価値があるもの（GitHub Trending）。Haiku に渡さず、配信元ごとに別の1通で送る。

どちらにするかは配信元ごとに決め、実行全体に一律でかけない。

## seen に入る3つの経路

seen は「もう送らなくてよい URL」の一覧で、「送った URL」の一覧ではない。入る経路が3つある。

| 経路 | いつ | なぜ入れるか |
|---|---|---|
| `alive` | seen にある URL が、まだフィードに載っていた | 新しい側へ移し、載り続けている間は押し出されないようにする |
| 送信した | 選別を通って送れた | 二度と送らない |
| 選別で落ちた | Haiku が選ばなかった | 翌日また判定させない（トークンの節約） |

入れないものも決めてある。

- 上限を超えて今回扱わなかった新着。翌日以降の候補に残す
- 送信に失敗した `Section` の記事。次の実行で送り直す
- `--dry-run` の回のすべて

## Section

Telegram に送る1通分（長ければ分割される）のまとまり。選別する配信元をまとめた1つと、選別しない配信元ごとの1つずつがある。`evaluated` は、送信に成功したときに seen に入れる URL の集合で、選別で落ちた分を含む。
